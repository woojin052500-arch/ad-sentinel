# AD Sentinel — 공공 웹사이트 불법광고 탐지 도구

공공 웹사이트의 하위 페이지·게시글·댓글·iframe에 게시되거나 숨겨진 불법광고(도박·성인물 등)를
자동으로 찾아 분류하고, 위치(페이지 URL + CSS 선택자)를 알려주는 도구입니다.

> 행정안전부·NIA 「공공 웹사이트 불법광고 탐지 도구 개발 공모전」 출품작

## 진행 현황

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 크롤러 (Playwright 렌더링, iframe·숨김 요소 수집) | ✅ |
| 2 | 탐지·분류 (키워드·숨김·도메인 점수, 화이트리스트, 페이지 간 묶기) | ✅ |
| 3 | GUI (사이트 점검, URL 목록 점검, 결과 상세, 보고서 내보내기) | ✅ |
| 4 | Windows exe 빌드 (PyInstaller) | ⏳ |
| 5 | 문서 (매뉴얼, 사용설명서, 기획서) | ⏳ |

## 화면 사용법 (GUI)

`python main.py` (인자 없이) 또는 exe를 실행합니다.

**화면 속 설명** - 설명서 없이 쓸 수 있도록 화면에 설명을 넣었습니다.
- 각 설정 옆의 **?** 에 마우스를 올리거나 누르면 "무엇인가요 / 언제 바꾸나요 / 추천" 세 줄 설명이 뜹니다.
  (최대 페이지 수, 링크 깊이, 입장 버튼 자동 클릭, sitemap·RSS 주소, 내가 관리하는 사이트 점검, 요청 간격,
  페이지당 제한 시간, 브라우저 창 보이기, 상세 로그 보기)
- 결과 표의 열 제목(판정 ?, 유형 ?, 분류 ?, 점수 ? …)에 마우스를 올리면 판정·유형·점수 뜻이 나오고,
  **⚠ 점검하지 못한 영역** 버튼 옆 **?** 와 목록 화면에 그 영역이 무엇이고 왜 확인해야 하는지 나옵니다.
- 최대 페이지 수 옆에 예상 소요 시간(한 페이지 약 5초 기준)이 바로 표시됩니다.
- 오른쪽 위 **처음 사용하시나요? [3단계 사용법] [설정·결과 설명]** 으로 사용법과 전체 설명을 볼 수 있고,
  처음 실행하면 오른쪽 상세 칸에도 3단계 사용법(주소 입력 → 점검 시작 → 결과 확인)이 나옵니다.
- 설명 문구는 `ad_sentinel/help_texts.py` 한 곳에 모여 있습니다. 사용설명서를 쓸 때는
  `python -m ad_sentinel.help_texts > help.md`로 같은 문구를 Markdown으로 뽑아 재사용할 수 있습니다.

1. **점검 방식** 선택
   - **사이트 점검**: 시작 주소를 넣으면 같은 사이트 안의 링크를 따라가며 하위 페이지를 점검합니다. 최대 페이지 수와 링크 깊이를 정할 수 있습니다.
     sitemap.xml이 있으면 먼저 읽어 점검 목록에 넣고, **첫 화면의 '입장' 버튼 자동 클릭**(기본 켜짐)으로 관문 페이지를 통과합니다.
   - **URL 목록 점검**: 주소 목록 파일에 있는 주소만 점검합니다. 링크는 따라가지 않습니다.
     txt(한 줄에 주소 하나), CSV(첫 번째 열), 구글 서치 콘솔에서 내보낸 파일(csv 또는 zip)을 그대로 읽습니다.
2. 필요하면 **내가 관리하는 사이트 점검 (robots.txt 무시)** 체크 → 확인 창에서 한 번 더 확인
3. **▶ 점검 시작** → 진행 상황(현재 페이지, N/M, 진행 바, 로그) 표시, **■ 중지**로 멈추면 그때까지 점검한 결과로 탐지
   - 로그는 기본적으로 쉬운 문구로 나옵니다. 예: `3번째 페이지 점검 완료: 공지사항 (이상 없음)`, `(의심 2건, 점검하지 못한 영역 1곳)`
   - **상세 로그 보기**를 체크하면 로딩·프레임별 추출 시간 같은 기술 로그를 함께 봅니다.
4. **점검 결과** 목록에서 항목을 누르면 오른쪽에 조치 안내, 근거, 발견 페이지, 위치(선택자), iframe 경로, 숨김 이유, 반사된 파라미터 표시.
   두 번 누르거나 **페이지 열기**를 누르면 브라우저로 엽니다.
   - 결과가 0건이어도 오른쪽에 **점검 요약**(점검 페이지 수, iframe 수, 검사한 요소 수, 점검하지 못한 영역, 소요 시간)이 나옵니다.
   - **⚠ 점검하지 못한 영역 N곳** 버튼: 응답이 없거나 불러와지지 않은 iframe, 열지 못한 페이지, robots.txt로 막힌 주소를
     주소·이유·신뢰 도메인 여부와 함께 보여 줍니다. 숨겨진 iframe은 불법광고의 주요 수법이므로 0건이어도 꼭 확인하세요.
5. **HTML 보고서 / CSV / JSON으로 저장**. CSV는 한글 엑셀에서 바로 열립니다.

그 밖의 기능
- **저장된 점검 결과 불러오기**: `output/crawl_*.json`을 고르면 다시 크롤링하지 않고 탐지만 다시 실행합니다. `detect_*.json`은 결과만 표시합니다.
- **신뢰 도메인 관리**: 기본 신뢰 도메인 외에 추가할 도메인을 입력합니다. 저장하면 `whitelist.txt`에 기록되고 현재 결과를 다시 탐지합니다.
- 점검할 때마다 `output/` 폴더에 `crawl_날짜_시간.json`(수집 원본)과 `detect_날짜_시간.json`(탐지 결과)이 자동 저장됩니다.

### 서치 콘솔 연계 흐름 (사용설명서용)

구글 서치 콘솔 → 실적 → 페이지 탭 → 내보내기(CSV 다운로드) → 이 도구에서 **URL 목록 점검** → **목록 파일 불러오기**로 받은 zip 또는 `페이지.csv` 선택 → 점검 시작.
검색엔진에 노출된 주소 중 파라미터 반사형 스팸 주소처럼 사이트 안에서는 링크로 연결되지 않는 주소를 점검할 수 있습니다.

### GUI 라이브러리: Tkinter를 쓴 이유

- **파이썬 표준 라이브러리**라 추가 설치가 없고, PyInstaller로 묶을 때 exe 크기가 PySide6(Qt)보다 수십 MB 작습니다.
- 필요한 화면 요소(입력칸, 표, 진행 바, 파일 선택 창)가 모두 있어 이 도구 규모에 충분합니다.
- 라이선스 확인(LGPL)이나 Qt 플러그인 동봉 같은 배포 문제가 없습니다.
- 코드가 단순해서 심사 때 구조를 설명하기 쉽습니다.
- 화면은 [sv-ttk](https://github.com/rdbende/Sun-Valley-ttk-theme)(Windows 11 스타일 테마, 라이트 모드)를 씁니다. 순수 Tcl 테마 파일이라
  PyInstaller 기본 훅(`hook-sv_ttk`)이 자동으로 포함하며, 설치되어 있지 않으면 기본 테마로 동작합니다.
- 고해상도(DPI 배율 125%·150% 등): 프로세스 DPI 인식을 **시스템 단위**(`SetProcessDpiAwareness(1)`, 파이썬 IDLE과 같은 방식)로 켜고,
  창 크기·열 너비·테마 글꼴(픽셀 단위)을 배율에 맞춰 키웁니다. 모니터별(Per-Monitor) 인식은 Tk 8.6이 모니터 사이 배율 변경을
  처리하지 못해 글자 잘림·겹침이 생길 수 있어 쓰지 않습니다.
- 창 크기: 최소 크기는 화면 내용이 필요로 하는 폭 이상으로 정해, 가장 작게 줄여도 모든 버튼이 보입니다. 결과 영역 윗줄은
  저장 버튼을 먼저 배치하고 요약 문구가 줄어들게 했습니다. 크기를 바꾸는 동안에는 말풍선을 닫고, 안내 문구 줄바꿈 폭은
  크기 조절이 멈춘 뒤(0.15초) 한 번만 다시 계산합니다. 창 바탕색을 테마 색과 맞춰 크기 조절 중 깜빡임을 줄였습니다.
- 아이콘: `ad_sentinel/assets/icon.ico`(창·exe 공용)와 `icon.png`·`icon_16~64.png`. `python packaging/make_icon.py`로 다시 만들 수 있습니다.
  창 아이콘은 `iconbitmap`(ico)과 `iconphoto`(여러 크기 png)를 함께 적용하고, Windows에서는 Win32 `WM_SETICON`으로 작은·큰 아이콘을
  한 번 더 지정합니다. (한글이 들어간 폴더 경로에서도 동작) 작업 표시줄이 python.exe 아이콘 대신 전용 아이콘을 쓰도록
  `SetCurrentProcessExplicitAppUserModelID`로 앱 ID(`ADSentinel.PublicWebAdScanner`)를 정합니다. 아이콘 설정에 실패하면 상세 로그에 이유가 남습니다.

## 설치 및 실행 (개발 환경)

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements-dev.txt
playwright install chromium       # 생략 시 Windows 기본 Edge를 자동 사용

python main.py https://www.example.go.kr --max-pages 20
python main.py --url-list 페이지.csv                            # URL 목록 점검
python main.py --from-json output/crawl_20260926_185056.json   # 기존 크롤링 결과로 탐지만 다시 실행
```

주요 옵션: `--max-pages`, `--depth`, `--delay`, `--page-timeout`, `--out`, `--report`, `--whitelist <도메인...>`, `--same-host-only`,
`--ignore-robots`, `--show-browser`, `--screenshots`, `--cloaking off|suspect|all`, `--browser <브라우저 경로>`

### 관문 페이지·SPA·sitemap.xml 처리

**관문(입장 버튼) 페이지** - `--no-gate`로 끌 수 있음, GUI: "첫 화면의 '입장' 버튼 자동 클릭"
- 첫 페이지에서 입장 버튼 후보를 찾습니다. 문구가 "입장, 들어가기, 시작하기, 시작, 계속하기, 둘러보기, Enter, Start" 등을
  **포함**하면 후보입니다. (예: "지금, 익명으로 시작하기 >", "커뮤니티 입장하기")
  - `href="javascript:..."` 링크, `onclick` 요소, `role=button`도 후보에 포함합니다.
  - 푸터 안 요소와 화면 안에서 스크롤만 하는 앵커(`href="#about"`)는 후보에서 뺍니다.
  - 버튼 크기로 순위를 매기고(입장 문구는 가중), 위에서부터 최대 3개를 차례로 시도합니다.
  - 본문 링크가 3개 이상인 페이지에서는 "확인·바로가기·go"처럼 흔한 문구와 **정확히 같은** 버튼은 누르지 않습니다.
- **링크 수와 관계없이** 한 번 눌러 보고, 로딩 화면이 끝나고 **화면 내용이 크게 바뀌면**(주소 변경, 글자·요소 수 30% 이상 변화)
  관문으로 인정합니다. 최대 `gate_wait_ms`(10초)까지 내용이 바뀌고 안정될 때까지 기다립니다.
  바뀌지 않으면 다음 후보를 시도하고, 끝내 바뀌지 않으면 `gate_attempt`에만 기록합니다.
- **본문 링크**를 셀 때 푸터 링크, 같은 페이지 앵커(`#...`), 이용약관·개인정보처리방침·서비스 안내·통계 같은 고정 링크는 뺍니다.
- 입장하면 로그에 `입장 버튼('지금, 익명으로 시작하기 >') 클릭 후 점검 계속 (화면 글자 165자 → 213자, 새 링크 0개)`가 표시됩니다.
- 입장 상태가 화면 상태로만 유지되는 SPA는 다른 페이지를 열 때 관문이 다시 나오므로, 처음 누른 것과 **같은 문구의 버튼만** 다시 누릅니다.
- **절대 누르지 않는 버튼**: 문구·주소·onclick·id·class에 로그인, 회원가입·가입, 결제·구매·주문, 삭제, 신고, 탈퇴, 로그아웃,
  비밀번호, 다운로드·설치, 구독·후원, 전송, **동의·수락·허용·쿠키, 디스코드** 등이 들어간 버튼, 비밀번호 입력칸이 있거나
  POST로 전송하는 폼 안의 버튼, 외부 사이트·메일·전화 링크 (`ad_sentinel/crawler/gate.py`의 `DANGER_WORDS`)
- **팝업**: 이용약관 "동의", 가입 권유 같은 팝업은 누르지 않고 **그대로 둔 채** 팝업 뒤 본문까지 추출합니다.
  (약관 동의를 도구가 대신하지 않기 위함) 팝업이 덮고 있어도 더보기 버튼은 JS 클릭으로 누릅니다.
- **방문하지 않는 주소**: 주소에 delete·remove·logout·withdraw·`act=del`·삭제·탈퇴 등이 들어간 링크는 GET으로도 방문하지 않습니다.
  (`url_utils.is_safe_to_visit`)

**더보기·무한 스크롤** (입장 후 같은 화면) - `load_more`, `load_more_max_clicks`(30회), `load_more_timeout_sec`(90초)
- 게시글 목록 끝의 "더보기, 더 불러오기, 게시글 더 불러오기, Load more, Show more" 버튼을 반복해서 누르고, 버튼이 없으면
  맨 아래로 스크롤해 추가 로딩(무한 스크롤)을 기다립니다. 새 내용이 두 번 연속 나오지 않거나 상한에 닿으면 멈춥니다.
- 추가 로딩은 화면 글자·요소·높이가 **늘어났는지**로 판단합니다. (게시글이 많이 쌓인 뒤에도 몇 개씩 붙는 것을 알아보기 위함)
- **누르지 않는 "더보기"**: 흐림 처리된 이미지 위에 겹친 "클릭하여 더보기"(이미지 보기)처럼 이미지 근처에 겹쳐 있거나,
  같은 문구로 게시글마다 반복되는 버튼은 게시글을 더 불러오는 버튼이 아니므로 누르지 않습니다.
- 다른 주소로 이동하는 "더보기" 링크(`href="list.do?page=2"`)는 누르지 않습니다. (링크로 따로 점검)
- 로그: `더보기 2회 클릭·스크롤 추가 로딩 3회, 게시글 영역 추가 수집 (화면 글자 303자 → 1432자)`

**로딩 화면** - 입장 버튼을 누른 뒤 아래 중 하나에 해당하면 로딩 화면으로 보고, 최대 `gate_wait_ms`(20초)까지 기다린 뒤
내용이 안정되면 추출합니다.
- 글자가 400자 미만이고 "로딩, 다운로드 중, 불러오는 중, 잠시만, Loading" 같은 문구가 보일 때
- 글자가 400자 미만이고 진행 막대·스피너(`progress`, `role=progressbar`, `aria-busy`, class·id에 loading·loader·spinner·progress·bar)가 보일 때
  (로딩 문구가 그림·캔버스·Shadow DOM에 있어 글자로 읽히지 않는 사이트 대비)
- **입장 후 글자가 크게 줄었을 때**(300자 미만이면서 입장 전의 30% 미만). 이 경우 글자가 다시 늘어나면(최저치의 2배 이상) 로딩이
  끝난 것으로 보고, 늘지 않은 채 5초 동안 그대로면 기다림을 멈추되 "다 불러와지지 않았을 수 있습니다" 경고를 남깁니다.
- 로그: `로딩 화면으로 보여 대기 중... (화면 글자 2895자 → 36자로 급감)`, 끝나지 않으면 `대기 시간(20초) 안에 로딩이 끝나지 않음`
- 입장 후 첫 화면에서는 `입장 후 새로 나타난 글 제목 N개를 수집했습니다. (예: …, 입장 전 화면 제목 M개는 제외)`를,
  더보기·스크롤로 새 글이 없으면 `더보기·추가 로딩 없음 (…)`을 표시해 피드 게시글을 실제로 모았는지 로그에서 확인할 수 있습니다.
  입장 전 랜딩 화면의 소개 문구 제목은 세지 않으며, 새 제목이 하나도 없으면 "피드 게시글을 수집하지 못했을 수 있습니다" 경고를 남깁니다.

**봇 차단 장치 안내** - 입장 후 로딩 화면에서 끝나지 않았고, 그 화면이나 사이트에 "브라우저 보안, VPN 사용 제한, 봇 차단,
자동화 프로그램, 비정상 접근, 캡차, captcha, checking your browser" 같은 보안 안내 문구가 있으면 결과 요약에
`사이트의 봇 차단 장치 때문에 일부 화면을 점검하지 못했을 수 있습니다. 관리하는 사이트라면 점검 도구를 허용 목록에 추가하세요.`
를 표시합니다. **차단 장치를 우회하는 기능은 넣지 않았습니다.** 공공기관 점검 도구가 사이트의 보안 장치를 속이거나
피해 가는 것은 적절하지 않으므로, 차단되면 안내만 하고 사이트 운영자가 허용하도록 합니다.

**진단 기능**
- **화면 캡처**: GUI에서 **상세 로그 보기**를 켜고 점검하면(CLI `--screenshots`) 첫 페이지 입장 버튼 클릭 직후와 로딩 대기가
  끝난 시점의 화면을 `output/screenshots/날짜_시간_gate1_clicked.png`, `..._gate1_waited.png`로 저장합니다.
  (`screenshot_dir` 설정, 기본은 저장 안 함)
- **브라우저 창 보이기**: GUI "고급 설정"의 **브라우저 창 보이기(진단용)**(CLI `--show-browser`)를 켜면 점검하는 브라우저 창이
  화면에 보입니다. 창을 숨긴 기본 상태와 결과를 비교해, 사이트가 화면 없는(headless) 브라우저에만 내용을 숨기는지 확인할 때 씁니다.
  진단용이며, 차단을 피하기 위한 기능이 아닙니다.

**SPA(React·Vue·Next.js 등)** - `<a href>` 없이 이동하는 요소의 주소도 링크로 수집합니다. (`source` 필드로 구분)
- `onclick`의 `location.href='...'`, `navigate('/x')`, `router.push({path: '/x'})`, `window.open('...')`, `goPage('...')` 등
- `data-href`, `data-url`, `data-link`, `data-route`, `data-path`, `routerlink` 속성
- 주소가 `#/경로` 형태(해시 라우팅)인 SPA는 주소로 페이지를 구분할 수 없어 개별 페이지로 점검하지 못합니다.

**sitemap·RSS** - `--no-sitemap`으로 자동 탐색을 끌 수 있음
- **직접 지정**: GUI "sitemap 또는 RSS 주소 (선택)" 입력칸, CLI `--sitemap URL`(여러 번 가능). 사이트 설정(robots.txt)을 바꿀 수 없어도
  비표준 위치(예: `https://commu.world/all/sitemap.xml`)의 게시글 목록을 읽을 수 있습니다.
- **자동 탐색 순서**: 지정 주소 → robots.txt의 `Sitemap:` 항목 → `/sitemap.xml`, `/sitemap_index.xml`, `/all/sitemap.xml`
  → (여기까지 찾은 주소가 50개 미만일 때만) `/rss`, `/feed`, `/rss.xml`. 각 주소는 점검 시작 때 한 번씩만 요청합니다.
- sitemap(urlset·sitemapindex·gzip), **RSS 2.0, Atom** 피드를 모두 읽습니다. RSS·Atom 항목 제목은 결과의 "게시글 제목"으로 씁니다.
- 같은 사이트 주소만 최대 5,000개(`max_sitemap_urls`)까지 점검 목록에 넣습니다. 최대 페이지 수보다 많으면
  `sitemap 주소 1,000개 중 499개만 점검합니다. (최대 페이지 수 500 설정, 모두 점검하려면 늘리세요)`를 표시합니다.

**대량 점검·차단 대비**
- **요청 간격**: 기본 1초 (`delay_sec`, GUI "고급 설정", CLI `--delay`). 페이지당 제한 시간도 고급 설정에서 바꿀 수 있습니다.
- **차단 감지**: HTTP 429, Retry-After가 있는 503, 403 연속 3회, 다른 주소의 "요청 속도 제한·과도한 요청·잠시 후 다시" 안내
  페이지로 이동된 경우(안내 페이지를 직접 방문한 것은 제외)를 차단으로 봅니다.
- 차단되면 요청 간격을 두 배로(최소 2초, 최대 30초) 늘리고 `Retry-After`가 있으면 그만큼 기다린 뒤 같은 주소를 다시 시도합니다.
  연속 3회(`throttle_max_consecutive`) 차단되면 멈추고 "사이트가 요청을 계속 제한해 … 멈췄습니다. 요청 간격을 늘리거나 …"를 안내합니다.
  차단 기록은 `meta.throttle_events`에 남습니다.
- **예상 소요 시간**: 진행 상황에 `37 / 1200 · 남은 시간 약 58분 9초` (남은 페이지 × 지금까지 평균 시간)를 표시합니다.
  전체 수는 최대 페이지 수와 실제로 남은 주소 수 중 작은 값입니다.

**오류 페이지·잘못된 시작 주소**
- 입장 버튼 후보에서 **"홈으로, 돌아가기, 메인으로, 뒤로, 이전, 처음으로, home, back"** 같은 이동·복귀 문구는 뺍니다.
  (오류·안내 페이지의 "홈으로 돌아가기"를 입장 버튼으로 잘못 누르는 문제 방지)
- HTTP 4xx·5xx이거나, 본문이 짧고(800자 미만) "찾을 수 없/404/존재하지 않/길을 잃/이동되었/없는 페이지" 같은 문구가 있으면
  (HTTP 200으로 오는 **소프트 404** 포함) 오류 페이지로 보고 입장 버튼을 누르지 않습니다. 시작 주소가 오류 페이지면
  "시작 주소가 오류 페이지입니다"를 안내하고, 오류 페이지는 "점검하지 못한 영역"에 올립니다.
- 시작 주소가 `.xml`, `.rss`, `.atom`, `/rss`, `/feed`로 끝나면 sitemap·RSS로 읽고 사이트 첫 화면부터 점검하며, sitemap 칸에 넣도록 안내합니다.
- sitemap·RSS 자동 탐색 후보가 없으면 상세 로그에 `/sitemap.xml 없음(404)`, `/rss 없음(sitemap·RSS 형식이 아님)`처럼 남깁니다.

**게시글 개별 페이지** - 게시글 페이지에서도 입장 버튼이 다시 나오면 첫 페이지에서 누른 것과 같은 문구의 버튼을 누르고,
동의 팝업은 누르지 않습니다. 다시 누른 뒤 **주소가 다른 페이지(예: 홈)로 바뀌면 그 결과는 버리고** 누르기 전 원래 페이지
내용으로 점검하며 경고를 남깁니다. 이런 일이 3번 생기면 이후 페이지에서는 입장 버튼을 누르지 않습니다. 첫 페이지가 아닌 곳에서는 입장 문구가 분명한 버튼만 누르고, 더보기는 진짜 더보기 버튼이 있을 때만
최대 3회·15초까지 누릅니다.

**같은 화면 반복 경고** - 제목과 본문이 똑같은 화면이 서로 다른 주소 3곳 이상에서 나오면
"게시글 대신 같은 화면이 반복 점검되고 있습니다"를 경고하고, 반복된 주소를 "점검하지 못한 영역"에 올립니다.
(게시글을 실제로 점검하지 못했는데 "이상 없음"으로 보이는 것을 막기 위함)

**게시글 제목 표시** - 각 요소에서 가까운 글 단위(`article`, `li`, class에 post·item·card·entry·comment 등)의 제목(h1~h5,
class에 title·subject)을 `context_title`로 수집하고, 결과에 `post_title`(없으면 RSS 항목 제목)로 표시합니다.
GUI 결과 목록은 `카지노 먹튀검증 바로가기 (글: 글 제목 7)`처럼, 상세·CSV·HTML 보고서에는 "게시글 제목"으로 나옵니다.

**게시판을 못 찾았을 때 안내** - 입장 버튼으로 화면이 바뀌지도 않았고, 첫 페이지 외에 본문 링크로 찾은 페이지가 하나도 없이
sitemap.xml·약관 같은 고정 링크로만 점검이 끝나면 `sitemap.xml에 있는 주소로만 N페이지를 점검했습니다. 게시판 페이지를 찾지 못했을 수 있습니다. …`를 표시합니다.
커뮤니티형 사이트는 게시글이 sitemap에 없는 경우가 많기 때문입니다.

**적게 끝났을 때 안내** - 최대 페이지 수의 20% 이하로 끝나면(5페이지 이상 차이):
`발견한 링크가 적어 N페이지만 점검했습니다. 입장 버튼이 있는 사이트라면 입장 후 주소를 시작 주소로 넣어보세요.`
를 로그·결과 요약·HTML 보고서에 표시합니다. 입장 버튼을 누른 뒤 링크를 충분히 찾았거나 sitemap으로 주소를 받은 경우는
사이트가 원래 작은 것이므로 표시하지 않습니다.

### robots.txt 무시 (`--ignore-robots`, GUI: "내가 관리하는 사이트 점검")

- **페이지 간 묶기**: 같은 프레임 경로·선택자·내용은 한 건으로 묶고 `"3개 페이지에서 발견"`처럼 표시합니다.
  숨김 요소 안의 링크처럼 이미 찾은 요소의 하위 요소는 따로 표시하지 않습니다.

### 탐지 유형 (`pattern`)

| 유형 | 조건 |
|---|---|
| URL 파라미터 반사 | 반사 근거가 있음. `reflected_params`에 반사된 파라미터 이름과 값 표시 → 불법광고 의심 |
| 악용 가능 지점 | 검색 파라미터(q, query, keyword, searchWrd 등)의 반사만으로 잡히고 다른 광고 근거가 없음 → 항상 **검토 필요** |
| 클로킹 의심 | 구글봇·구글 검색 경유·모바일로 열었을 때만 광고 키워드, 외부 이동, 의심 도메인 링크가 나타남 |
| 자동 이동 | meta refresh 또는 다른 사이트로 이동 |
| 키워드 도배 | 페이지 전체에서 광고 키워드가 20회 이상·3종 이상·평균 2회 이상 반복되고, 본문 글자의 20% 이상이 키워드이거나 키워드만 나열한 줄이 3개 이상 (해킹 생성 페이지 의심) |
| 검색어 목록 오염 | 인기·최근·실시간 검색어, 검색어 순위 위젯 안에 광고 키워드나 텔레그램 ID가 있음 |
| 숨김 광고 | 숨김 근거가 있음 |
| 노출 광고 | 그 밖의 경우 |

**클로킹 검사** (GUI 고급 설정 "클로킹 검사", CLI `--cloaking suspect|all`, 기본 꺼짐)
해킹된 사이트가 구글봇에게만, 또는 구글 검색으로 들어오거나 휴대폰으로 접속할 때만 광고를 보여 주는 수법입니다.
관리자가 주소창에 직접 입력하면 정상으로 보여 발견이 어렵습니다.
- 같은 페이지를 ① 일반 PC ② 구글봇 User-Agent ③ Referer `https://www.google.com/` ④ 모바일 User-Agent(412×915, 터치)로
  새 브라우저 세션에서 각각 열고, 화면 글자·숨김 요소·링크·meta refresh·스크립트 이동 주소를 모아 일반 PC와 비교합니다.
- 일반 PC에는 없는데 특정 방식에서만 광고 키워드, 신뢰 도메인 밖으로 이동, 의심 도메인 링크, 텔레그램 ID가 나오면
  "클로킹 의심"입니다. 결과 상세에 "구글봇으로 볼 때만 나타남", 같은 단어 비율, 새 키워드, 이동 주소, 제목 변화가 표시됩니다.
- 모바일 화면이 원래 다른 사이트처럼 **내용 차이만 있고 광고 흔적이 없으면** 판정하지 않습니다.
- 검사 범위: `첫 페이지·의심 페이지만`(첫 페이지와 광고 키워드·숨김 링크·자동 이동이 있는 페이지) 또는 `모든 페이지`.
  검사한 페이지마다 4번 열어 몇 초씩 더 걸립니다.
- 한계: 구글의 실제 접속 주소(IP 역조회)까지 확인하는 클로킹은 User-Agent만으로 재현되지 않습니다. 구글 서치 콘솔의
  "URL 검사"로 구글이 보는 화면도 함께 확인하도록 조치 안내에 적었습니다.

**검색어 목록 오염**: 공공기관 내부 검색에서 텔레그램 ID와 마약·환전 용어를 반복 검색해 인기·최근 검색어 목록에 올리고,
그 페이지를 구글에 노출시키는 수법입니다. 추출 단계에서 "인기 검색어, 최근 검색어, 실시간 검색어, 검색어 순위, 추천 검색어" 제목이나
`popular-keyword`, `search-rank` 같은 class·id를 가진 목록을 찾아, 그 안의 글·링크에 `search_widget` 표시를 붙입니다.
정상 검색어(여권, 주민등록 등)는 키워드가 없으니 나오지 않습니다.

**숨은 위치**: `<title>`(기존), meta description·keywords, `og:title`·`og:description`·`og:site_name`, `twitter:title`·`twitter:description`,
링크가 아닌 이미지의 `alt`·`title`(숨긴 이미지는 숨김 요소로), `<noscript>` 안 글·링크도 검사합니다. 화면에는 안 보이지만 검색 결과
미리보기와 검색엔진에 노출되는 곳이라 숨김 근거(2점)를 붙입니다.

**URL 파라미터 반사**: 주소 파라미터를 화면에 그대로 출력하는 페이지를 악용한 스팸입니다.
예: `http://old.gongdan.go.kr/home.jsp?play=바카라분석`. 페이지 주소의 쿼리 파라미터 값(UTF-8, 실패 시 EUC-KR로 해석)이
요소 내용이나 페이지 제목에 들어 있고, **그 값 자체에 광고 키워드나 의심 도메인이 있을 때만** 근거로 인정합니다.
`?menu=공지사항`, `?q=주민등록`처럼 평범한 값의 반사는 무시합니다. 검색 페이지가 `?q=카지노 규제`를 출력하는 것처럼
의도가 정상이어도 구조가 같으면 잡히지만, 다음 조건을 모두 만족하면 **악용 가능 지점(검토 필요)**으로 따로 분류하고
"입력값을 그대로 출력하지 않도록 조치 권장" 안내를 붙입니다.

- 반사된 파라미터가 모두 검색용 이름(q, query, keyword, searchWrd 등)
- 반사된 값 밖의 텍스트에 광고 키워드·연락처가 없고, 숨김·의심 도메인·자동 이동 근거도 없음
- 반사된 값 자체도 광고 문구로 보기 어려움 (키워드 1개뿐이고 연락처 없음)

gongdan 사례(`play`는 검색 파라미터가 아님)나 `?q=바카라사이트 텔레그램 @xxx`처럼 값 자체가 광고 문구인 경우는
**URL 파라미터 반사(불법광고 의심)**입니다.

### 숨김 판정 기준 (`hidden_reasons`)

| 값 | 의미 |
|---|---|
| `display:none` / `visibility:hidden` / `opacity:0` | CSS로 감춤 |
| `off-screen` | 화면 밖 좌표(예: `left:-9999px`)로 밀어냄 |
| `text-indent` | `text-indent:-9999px` 로 글자를 밀어냄 |
| `zero-size` / `clip` | 크기 0·잘라내기로 감춤 |
| `tiny-font` | 글자 크기 2px 미만 |
| `same-color-as-background` / `transparent-text` | 글자색이 배경색과 같거나 투명 |
| `tiny-size` (iframe) | 2px 이하 크기의 iframe |

> 참고: 드롭다운 메뉴, 팝업, 스크린리더용 문구(`.blind`, `.sr-only`)도 숨김 요소로 수집됩니다.
> 크롤러는 **빠짐없이 수집**하는 역할이고, 광고 여부 판단은 2단계 탐지기에서 내용으로 합니다.
