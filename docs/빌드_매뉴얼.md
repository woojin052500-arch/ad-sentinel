# AD Sentinel 빌드 매뉴얼 (초안)

소스 코드에서 Windows용 실행 파일(`AD-Sentinel.exe`)을 만드는 방법입니다.
Windows 10/11 64비트 PC 한 대와 인터넷 연결만 있으면 됩니다. 모든 명령은 **명령 프롬프트(cmd)** 기준입니다.

---

## 1. 결과물

빌드가 끝나면 아래 두 가지가 생깁니다.

```
dist\
├── AD-Sentinel\                      ← 배포 폴더 (이 폴더째 복사해서 사용)
│   ├── AD-Sentinel.exe               ← 실행 파일 (방패 아이콘)
│   ├── _internal\                    ← 실행에 필요한 파일 (지우지 말 것)
│   ├── licenses\                     ← 포함된 오픈소스 구성요소의 라이선스 원문
│   └── THIRD_PARTY_NOTICES.txt       ← 제3자 구성요소 고지
└── AD-Sentinel-0.1.0-win64.zip       ← 위 폴더를 압축한 배포 파일
```

실행하면 exe 옆에 다음 파일·폴더가 자동으로 생깁니다.

| 이름 | 내용 | 생기는 때 |
|---|---|---|
| `output\` | 점검 결과(JSON), 저장한 보고서, 진단용 화면 캡처 | 첫 점검 때 |
| `whitelist.txt` | 사용자가 추가한 신뢰 도메인 | "신뢰 도메인 관리"에서 저장할 때 |
| `ui_settings.json` | 화면 설정(가벼운 화면 켬/끔) | 고급 설정에서 바꿀 때 |
| `error.log` | 예상하지 못한 오류 기록 | 오류가 났을 때만 |

exe 폴더에 쓸 권한이 없으면(예: `C:\Program Files` 아래에 둔 경우) 대신
`%LOCALAPPDATA%\AD-Sentinel\` 폴더에 만듭니다.

## 2. 필요한 프로그램 설치

### 2-1. Python 3.12 (64비트)

1. https://www.python.org/downloads/windows/ 에서 **Python 3.12.x Windows installer (64-bit)** 를 받습니다.
2. 설치 첫 화면에서 아래 두 가지를 꼭 체크합니다.
   - **Add python.exe to PATH**
   - **Use admin privileges when installing py.exe** (py 런처 설치)
3. **Install Now**로 설치합니다. 기본 설치에 Tcl/Tk(화면 라이브러리)가 들어 있으니 따로 받을 필요가 없습니다.
4. 새 명령 프롬프트를 열고 확인합니다.

   ```bat
   py -3.12 --version
   ```

   `Python 3.12.x`가 나오면 됩니다.

> Microsoft Store 판 Python은 쓰지 마세요. 설치 경로가 특수해 PyInstaller가 일부 파일을 찾지 못할 수 있습니다.
> 3.10·3.11·3.13에서도 동작하도록 작성했지만, 검증은 3.12로 했습니다.

### 2-2. 소스 코드

- 압축 파일로 받은 경우: 원하는 곳에 압축을 풉니다.
- Git을 쓰는 경우: `git clone <저장소 주소>`

**권장 위치**: `C:\build\ad-sentinel`처럼 **영문·숫자로만 된 짧은 경로**.
한글·공백이 들어간 경로(예: `C:\Users\홍길동\바탕 화면\…`)에서도 동작하도록 만들었지만,
일부 도구가 경로 문자를 잘못 해석하는 경우가 있어 영문 경로를 권장합니다.

### 2-3. 웹 브라우저

빌드에는 필요 없습니다. 실행할 때 **PC에 설치된 Microsoft Edge**를 씁니다(Windows 10/11 기본 포함).
Edge가 없거나 막혀 있으면 Google Chrome을 대신 씁니다. Chromium 같은 브라우저를 exe에 넣지 않으므로
`playwright install` 명령은 **실행하지 않아도 됩니다.**

## 3. 빌드 (자동)

소스 폴더에서 다음을 실행합니다. (탐색기에서 `packaging\build.bat`을 더블 클릭해도 됩니다)

```bat
cd C:\build\ad-sentinel
packaging\build.bat
```

`build.bat`이 하는 일:

1. `py -3.12`(없으면 `python`)를 찾습니다.
2. 소스 폴더에 빌드 전용 가상 환경 `.build-venv\`를 만듭니다. (PC의 다른 Python 설정에 영향 없음)
3. `requirements-build.txt`에 적힌 패키지(playwright, sv-ttk, pyinstaller)를 설치합니다.
4. `packaging\ad_sentinel.spec`으로 PyInstaller 빌드를 합니다.
5. 라이선스 파일과 `THIRD_PARTY_NOTICES.txt`를 배포 폴더에 복사합니다.
6. 배포 폴더를 zip으로 압축합니다.

처음에는 패키지를 받느라 시간이 더 걸리고(대략 수 분), 다시 빌드할 때는 그보다 빠릅니다.
마지막에 `Done.`이 나오면 성공입니다.

---

## 4. 빌드 (수동, 단계별)

`build.bat`이 실패할 때 원인을 찾기 위해 같은 과정을 하나씩 실행하는 방법입니다.

```bat
cd C:\build\ad-sentinel
set PYTHONUTF8=1
py -3.12 -m venv .build-venv
.build-venv\Scripts\python.exe -m pip install --upgrade pip
.build-venv\Scripts\python.exe -m pip install -r requirements-build.txt
.build-venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --distpath dist --workpath build packaging\ad_sentinel.spec
.build-venv\Scripts\python.exe packaging\collect_licenses.py dist\AD-Sentinel
```

빌드 전에 소스 상태로 실행해 보려면:

```bat
.build-venv\Scripts\python.exe main.py
```

## 5. 빌드 설정 설명 (`packaging\ad_sentinel.spec`)

| 항목 | 설정 | 이유 |
|---|---|---|
| 방식 | **onedir** (폴더 하나) | 아래 6장 참고 |
| 콘솔 창 | 띄우지 않음 (`console=False`) | 일반 사용자에게 검은 창이 보이지 않게 |
| 아이콘 | `ad_sentinel\assets\icon.ico` | exe 파일·창·작업 표시줄에 방패 아이콘 |
| 버전 정보 | 파일 속성 → 자세히에 제품명·버전 표시 | 정체를 알 수 없는 exe로 보이지 않게(백신 오탐 완화에 도움) |
| UPX 압축 | 사용 안 함 | UPX로 압축한 exe는 백신 오탐이 크게 늘어남 |
| 함께 넣는 파일 | `ad_sentinel\assets`(아이콘), `ad_sentinel\detector\data`(confusables.txt, LICENSE-UNICODE.txt), sv-ttk 테마 파일 | 실행 중 읽는 데이터 |
| 넣지 않는 것 | `demo_server.py`, `tests\`, pytest, Pillow 등 개발용 | 배포 크기·혼란 줄이기 |
| 브라우저 | 넣지 않음 (Edge 사용) | 배포 크기 약 150MB 절약, 브라우저 보안 업데이트는 Windows가 담당 |

작업 표시줄 아이콘: 실행 파일의 아이콘과 함께, 프로그램이 시작할 때 Windows에 전용 앱 ID
(`ADSentinel.PublicWebAdScanner`)를 등록하고 창 아이콘을 직접 지정하므로, `python main.py`로 실행할 때처럼
파이썬 아이콘으로 묶이지 않고 방패 아이콘으로 표시됩니다.

## 6. onefile과 onedir 중 onedir을 고른 이유

| 기준 | onefile (exe 하나) | **onedir (폴더)** |
|---|---|---|
| 실행 속도 | 실행할 때마다 임시 폴더에 약 170MB를 풀어서 첫 화면까지 수 초~십수 초 | 바로 실행 (풀기 과정 없음) |
| 백신 오탐 | "실행하면서 자기 안의 파일을 풀어 실행"하는 동작이 악성코드와 비슷해 오탐이 잦음 | 일반 프로그램 설치 폴더와 같은 구조라 오탐이 적음 |
| 용량 | 압축되어 조금 작음 | 비슷함 (zip으로 배포하면 차이 거의 없음) |
| 임시 폴더 | 비정상 종료 시 `%TEMP%`에 풀린 파일이 남음 | 없음 |
| 결과 파일 위치 | exe 옆 `output\` (동일) | exe 옆 `output\` |
| 배포 | 파일 하나라 간단 | 폴더째(또는 zip) 전달 |

점검 도구는 Playwright 드라이버(약 135MB)를 포함해 크기가 커서, onefile로 하면 **매번 실행이 느려지고 백신 오탐 위험이 커집니다.**
그래서 onedir로 빌드하고, 배포는 폴더를 압축한 zip 하나로 합니다.

## 7. 한국어 Windows(cp949) 주의사항

한국어 Windows는 기본 문자 인코딩이 cp949라서, UTF-8 파일을 그대로 읽으면 오류가 나는 경우가 있습니다.

| 증상 | 원인 | 대응 (이미 반영된 것) |
|---|---|---|
| `pip install -r requirements.txt`에서 `UnicodeDecodeError: 'cp949' codec…` | requirements 파일에 한글 주석 | requirements 파일은 **영문(ASCII)만** 쓰도록 유지 |
| `build.bat` 실행 시 한글이 깨지거나 명령이 이상하게 실행됨 | 배치 파일을 cmd가 cp949로 읽음 | `build.bat`은 **영문(ASCII)만** 사용, `chcp` 변경 안 함 |
| PyInstaller·pip 실행 중 인코딩 오류 | 파이썬이 cp949로 파일을 엶 | `build.bat`에서 `PYTHONUTF8=1`(UTF-8 모드) 설정. 수동 빌드 때도 `set PYTHONUTF8=1` |
| 명령 프롬프트에서 `AD-Sentinel.exe <주소>`로 실행한 결과 한글이 깨짐 | 콘솔 코드 페이지 | 콘솔 기본 인코딩(cp949)으로 출력하도록 처리함 |

직접 파일을 고칠 때:

- `.py`, `.md`, `.txt`, `.spec` 파일은 **UTF-8**로 저장하세요. 메모장의 "ANSI" 저장은 cp949라서 쓰면 안 됩니다.
- `requirements*.txt`, `packaging\build.bat`에는 **한글을 넣지 마세요.**

## 8. Python이 없는 깨끗한 Windows 11에서 확인할 것 (심사위원 PC 상황)

가장 쉬운 방법은 **Windows 샌드박스**(Windows 11 Pro 이상, "Windows 기능 켜기/끄기"에서 켬)입니다.
Python이 없는 새 Windows가 매번 새로 열려 심사위원 PC와 거의 같은 조건에서 확인할 수 있습니다.

| # | 확인 항목 | 기대 결과 |
|---|---|---|
| 1 | zip을 받아 압축 풀기 → `AD-Sentinel.exe` 실행 | SmartScreen 경고가 뜨면 "추가 정보 → 실행" (9장 참고) 후 창이 열림 |
| 2 | 창 제목 표시줄·작업 표시줄 아이콘 | 방패 아이콘 (파이썬·기본 아이콘 아님). 작업 표시줄에 고정해도 방패 |
| 3 | 실행 중 검은 콘솔 창 | 뜨지 않음 |
| 4 | 공개 사이트 주소(예: `https://www.mois.go.kr`) 넣고 점검 시작 | Edge가 화면 없이 실행되어 점검 진행, 결과 표시 |
| 5 | exe 옆 `output\` 폴더 | 점검 결과 JSON 생성 |
| 6 | "신뢰 도메인 관리"에서 도메인 추가·저장 | exe 옆 `whitelist.txt` 생성 |
| 7 | 고급 설정 → "가벼운 화면" 끄기·켜기, 프로그램 다시 실행 | `ui_settings.json` 생성, 설정 유지 |
| 8 | 창 최대화, Win+←/→ 스냅(화면 절반), 스냅 레이아웃(1/3) | 화면 왼쪽이 잘리지 않음. 창이 좁으면 아래에 가로 스크롤 막대가 생김 |
| 9 | 디스플레이 배율 100% / 125% / 150% | 글자·버튼이 잘리지 않고 흐리지 않음 |
| 10 | HTML 보고서·CSV 저장, CSV를 엑셀로 열기 | 한글이 깨지지 않음 |
| 11 | 사용자 이름이 한글인 계정, 한글이 들어간 폴더에 압축 풀기 | 정상 실행·저장 |
| 12 | `C:\Program Files\` 아래에 복사해 실행(쓰기 권한 없음) | `%LOCALAPPDATA%\AD-Sentinel\output\`에 결과 저장 |
| 13 | 기관망·프록시 환경 | 점검이 진행되는지 확인 (아직 프록시 환경에서는 검증하지 않음) |
| 14 | Edge가 정책으로 막힌 PC | "브라우저를 실행하지 못했습니다" 한국어 안내 창 (해결 방법 포함) |
| 15 | 인터넷 없이 실행 | 창은 열리고, 점검 시 페이지를 열 수 없다는 안내 |

참고: `demo_server.py`(시연용 샘플 사이트)는 exe에 넣지 않았으므로 Python이 없는 PC에서는 실행할 수 없습니다.
심사용 시연이 필요하면 공개된 기관 누리집으로 점검하거나, 샘플 사이트를 별도 웹 서버에 올려 두는 방법을 검토하세요.

## 9. Windows Defender·SmartScreen 오탐

### 왜 생기나

- **SmartScreen**: 인터넷에서 받은(zip에 "웹에서 받은 파일" 표시가 붙은) **서명되지 않은 exe**는 다운로드 수가 적으면
  "Windows의 PC 보호" 창을 띄웁니다. 악성코드라는 뜻이 아니라 **평판 정보가 없다**는 뜻입니다.
- **Defender(백신)**: PyInstaller로 만든 exe는 구조가 비슷한 악성코드가 있어 가끔 오탐합니다. 특히 onefile, UPX 압축,
  오래된 PyInstaller 버전에서 잦습니다.

### 이미 적용한 것

- onedir 빌드, UPX 미사용, 최신 PyInstaller 사용
- exe에 버전 정보(제품명·설명·버전) 포함
- 브라우저를 내장하지 않고 PC의 Edge 사용 (실행 파일 수·크기 감소)

### 추가로 할 수 있는 것

| 방법 | 효과 | 비고 |
|---|---|---|
| **코드 서명 인증서**(OV 또는 EV)로 `AD-Sentinel.exe` 서명 | SmartScreen·백신 오탐을 가장 확실히 줄임. EV는 즉시 평판 확보 | 유료(연 수십만 원), 기관 명의 필요 |
| Microsoft에 오탐 신고 (https://www.microsoft.com/wdsi/filesubmission) | Defender 오탐 해제 | 보통 수일 내 처리 |
| 배포 전 VirusTotal 등으로 검사 | 오탐 여부 미리 확인 | 결과 화면을 제출 자료에 첨부 가능 |
| 받은 zip을 압축 풀기 전에 "속성 → 차단 해제" 체크, 또는 PowerShell `Unblock-File` | SmartScreen 경고 없이 실행 | 심사위원 안내문에 적어 두기 |
| USB 등으로 전달 | "웹에서 받은 파일" 표시가 붙지 않아 SmartScreen이 덜 뜸 | |
| PyInstaller 부트로더를 직접 컴파일 | 흔한 부트로더 서명과 달라져 오탐 감소 | 고급, Visual Studio 빌드 도구 필요 |

심사위원 안내 예시: "실행 시 'Windows의 PC 보호' 창이 나오면 **추가 정보 → 실행**을 누르세요.
코드 서명 인증서가 없는 공모전 출품작이라 표시되는 안내이며, 소스 코드와 빌드 방법은 함께 제출했습니다."

## 10. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `build.bat`에서 `Python 3.12 was not found` | Python 설치 때 "Add python.exe to PATH" 체크 여부, 새 명령 프롬프트에서 다시 실행 |
| pip 설치 중 네트워크 오류 | 기관망 프록시: `set HTTPS_PROXY=http://프록시주소:포트` 후 다시 실행 |
| `UnicodeDecodeError: 'cp949'` | `set PYTHONUTF8=1` 후 다시 실행, requirements 파일에 한글이 들어가지 않았는지 확인 |
| exe를 실행해도 아무 창도 안 뜸 | exe 옆(또는 `%LOCALAPPDATA%\AD-Sentinel\`)의 `error.log` 확인 |
| "브라우저를 실행하지 못했습니다" | Edge를 직접 한 번 열어 업데이트, 기관 보안 정책(원격 디버깅 차단) 여부를 전산 담당자에게 확인 |
| 백신이 exe를 삭제함 | 9장 참고, 빌드 폴더(`dist\`)를 백신 검사 예외로 두고 다시 빌드 |
| 아이콘이 예전 것으로 보임 | Windows 아이콘 캐시 문제. exe 이름을 바꾸거나 탐색기 재시작 |
